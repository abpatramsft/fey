Review

Read why the tree changed before reading every changed line.

Drift groups the live working tree into logical flows with intent and authorship, while preserving the raw diff as the evidence underneath.

A diff is precise about text and often weak at explaining purpose. Fey does not replace the diff; it adds the missing review layer and keeps the source one click away.

What counts as drift

Fey uses git as the source of truth:

  • Tracked changes are read from git diff HEAD.
  • Net-new files come from git ls-files --others --exclude-standard.
  • Ignored files stay out of the view.
  • Fey and GitHub configuration under .fey/ and .github/ stay out of product-code drift.

This is intentionally narrower than a content-hash freshness system. Drift means “what is currently ready to review in this working tree.”

Stable hunk signatures

Fey flattens the current diff into hunks and gives each one a stable signature. Drift notes refer to those signatures rather than to a fragile ordinal position.

A flow is the unit of explanation

Related hunks can belong to one change story even when they span files. A useful flow answers four questions:

What changed?
A short title names the behavior a reviewer controls or recognizes.
Why?
The summary and per-hunk rationale explain the operational reason for the edit.
Who led it?
The flow is marked AI-led, human-led, or mixed using local session evidence and known edits.
What proves it?
The raw diff stays collapsible under the explanation, linked to the actual file.

Claims affected by a change

When a changed line overlaps a wiki anchor, Fey raises that claim inside the flow. This gives the reviewer a specific documentation question: does the claim still describe the new code?

Review is git-independent. A maintainer can confirm a claim without committing the code, and the Drift badge counts only claims that still need attention.

Line overlap is a prompt to review

A change outside an anchored range can still alter a claim semantically. Fey makes obvious overlap visible; it does not pretend to solve every dependency relationship.

Authorship is stated, not guessed silently

The visual spine and label distinguish AI-led, human, and mixed flows. When session history is available, the flow can include the stated intent that led to the change. If attribution is missing, the interface says so.

StateMeaning
AI-ledThe change is primarily connected to an agent-authored task or session intent.
HumanThe change is attributed to direct human work or an explicit operator decision.
MixedThe logical flow contains meaningful contributions from both.
UnattributedNo accepted note explains the current hunk. The optional drift gate fails until it is resolved.

Ask about a change

Each drift flow exposes an Ask action. Fey sends the flow title, summary, intent, authorship, hunk rationale, and actual diff to a read-only local Copilot CLI process. Copilot can open the changed files for surrounding context.

read-only Copilot boundary
copilot -C <repo> -s --no-ask-user \
  --available-tools view rg glob \
  --allow-all-tools \
  --deny-tool=write --deny-tool=shell

The available-tool list removes shell, write, web, and MCP integrations from the model’s tool surface. The prompt is passed on standard input rather than the command line, which avoids operating-system argument-length limits on large pages or diffs.

The drift attribution gate

check attribution
node .github/skills/fey-create/bin/fey.js drift-gate .

When the hook bundle is installed, agentStop includes this check. It blocks handoff while any visible hunk lacks a note. Re-running the exact same turn does not help; the agent must explain or remove the drift.

When there are no notes

The Drift view still renders the working tree. It falls back to a simple flow shape rather than showing nothing, but missing rationale remains explicit. This keeps failure useful without turning absence into success.
