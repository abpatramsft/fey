Improve · Operations

Hold the agent at the boundaries that matter.

Fey’s hook bundle adds context before work, prevents common gate bypasses, validates proposal and stop states, and remains inert in repositories without Fey state.

Hooks are thin lifecycle adapters. The durable rules live in the deterministic CLIs, so the same check can run manually, in a hook, or later in CI.

Install the hook bundle

Copy every fey-hook.* file into the repository’s .github/hooks/ directory. The JSON file registers lifecycle events; the Node dispatcher locates the installed Fey skills and returns the correct Copilot hook response.

repository hook layout
.github/hooks/
├── fey-hook.json
├── fey-hook.js
├── fey-hook.sh
└── fey-hook.ps1

The shell and PowerShell files remain compatibility wrappers for the stop hook. The registered events call the shared Node dispatcher, avoiding duplicated policy logic and removing a separate jq dependency.

Safe by default outside Fey

If a repository has no .fey/ state, the hook returns no decision and does not trap unrelated work. If an active improve run exists but the improve skill is missing, mutation and stop decisions fail closed so a half-installed gate cannot silently approve work.

Improve stop state

An active improve run may stop only when production code is clean, no candidate remains pending, a baseline exists, and the status is deliberately paused or done.

manual improve stop check
node .github/skills/fey-improve/bin/fey-improve.js stop-check <worktree>

Why direct git mutations are blocked

commit-if-better binds the current working tree to recorded evidence, checks the score and protected criteria, stages only evaluated paths, and records the decision. A direct git commit, git reset, git mv, or git apply can bypass or confuse that contract.

The pre-tool hook denies common mutating subcommands inside an active improve worktree. This is a guardrail, not an operating-system sandbox. The acceptance gate still recomputes and verifies state before a commit.

Timeout behavior

Copilot pre-tool hook timeouts are fail-open. Fey keeps the hook quick and gives it a larger timeout, but the deterministic candidate and acceptance gates remain the final boundary.

Proposal isolation

While a run is proposing, edit tools may write only below .fey/improve/scratch/. Returning to running independently verifies the proposal set and confirms that production code stayed unchanged.

This second check matters because some built-in subagents do not emit lifecycle events. Fey does not make proposal correctness depend on a hook that may not fire.

Source checkout versus worktree

The shared git directory holds a pointer to the active improve worktree. A session opened in the source checkout receives context about that run, but Fey does not block normal source-checkout edits. The user may keep working in parallel, accepting that later finalization can conflict.

After finalize, the source checkout contains the landed .fey/improve/ record. The hook reads its recorded worktree path and does not mistake the source checkout for the optimization environment.

Local CLI and cloud agent

Repository-level .github/hooks/*.json is the safest shared path because Copilot cloud agent loads hooks from the cloned repository and honors Bash entries. Local Copilot CLI selects PowerShell on Windows and Bash elsewhere.

User-installed plugin hooks are part of the future packaging plan, but cloud support should continue to keep an explicit repository-level option rather than assuming a local plugin cache exists in an ephemeral environment.

Debug a hook

Run the deterministic command first. If it behaves correctly, pipe a representative payload into the dispatcher and verify the final JSON decision.

PowerShell example
'{"cwd":"C:\\repo","stopReason":"end_turn","stop_hook_active":false}' |
  node .github\hooks\fey-hook.js agentStop

Progress lines are JSON objects with "type": "progress". The final non-progress object contains the allow, deny, or block result consumed by Copilot.
