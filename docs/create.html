Create

Turn source into an explanation with a checkable spine.

Fey lets Copilot choose how to explain a repository while deterministic commands own span extraction, validation, reduction, coverage, and readiness.

The create flow is deliberately asymmetric: the indexer and validators are strict; the page structure and prose remain free to fit the repository in front of them.

RepositoryFiles, symbols, entry points
CatalogValidated source spans
BundlePages, diagrams, drift notes

The create flow

01

Inspect the repository

Understand its languages, architecture, public entry points, and what a reader needs first. This determines the indexer and page plan.

02

Build the span catalog

Prefer a generated .fey/create/indexer.mjs tailored to the repository. Use the built-in multi-language extractor as a fallback.

03

Author pages against accepted IDs

Each prose block names one or more span IDs from the catalog. No page may invent a symbol or line range and hope it exists.

04

Attribute working-tree drift

If the repository has uncommitted changes, describe the intent and authorship of every visible diff hunk before handoff.

05

Serve and hold the boundary

Start the viewer. When hooks are enabled, coverage, attributed drift, and dashboard liveness must pass before the agent can stop.

The generated indexer

A generic parser is convenient, but real repositories mix languages, generated code, frameworks, and naming conventions. Fey’s preferred path is a small per-repository Node script written after inspection.

.fey/create/indexer.mjs · output contract
{
  "spans": [
    {
      "file": "src/orders/service.py",
      "symbol": "OrderService.place_order",
      "kind": "method",
      "startLine": 24,
      "endLine": 68
    }
  ]
}

The script receives the repository root as its first argument and prints only JSON to standard output. Logs go to standard error. Fey derives the final span ID and content hash, then verifies that the file and line range exist and that IDs are unique.

Write nothing by hand

The indexer authors spans. Copilot should never type span records directly into the manifest, because that would make refreshes non-repeatable.

Built-in fallback

When no repository-specific indexer exists, fey index falls back to built-in extraction for TypeScript and JavaScript, Python, and common brace-based languages such as Go, Rust, Java, C#, C/C++, Kotlin, Swift, Scala, and PHP. JavaScript and TypeScript use the compiler API when the optional typescript package is present and otherwise use the dependency-free brace scanner.

force the built-in extractor
node .github/skills/fey-create/bin/fey.js index . --builtin

Install the optional compiler dependency when exact JavaScript/TypeScript AST extraction matters:

optional TypeScript compiler API
npm install --prefix .github/skills/fey-create

Authoring modes

One pass for a small repository

For a compact codebase, one agent can inspect the full span catalog, choose the page structure, author the pages, and build the overview. The important constraint is not the number of agents; it is that every claim resolves to accepted evidence.

Map and reduce for a large repository

For a multi-module repository, partition the files into non-overlapping units. Parallel agents write their page, block metadata, and unit record into isolated scratch directories. They return a receipt rather than sending all prose back through the parent context.

parallel authoring scratch contract
.fey/create/scratch/<unit-id>/
├── unit.json
├── page.md
└── blocks.json

fey merge validates every unit, ensures page and block IDs are unique, checks marker parity, preserves locked blocks, and writes the final pages only when the entire reduction is valid.

deterministic reduce
node .github/skills/fey-create/bin/fey.js merge .

What the viewer builds around the pages

Overview
A repository description, named architecture layers, suggested reading path, and source coverage.
Wiki
Editable prose blocks beside the exact files and line ranges they explain.
Diagrams
Entry-point control paths whose resolved nodes link back to accepted spans.
Drift
The current working tree grouped into logical flows with intent, authorship, and raw diff evidence.
Optimize
The hill-climb history from .fey/improve/, even when no create bundle exists.

Coverage is a reading signal, not a truth score

Coverage measures the percentage of indexed source lines touched by at least one anchor. It tells a maintainer where the explanation is thin. It does not prove that a sentence is semantically correct.

.fey/create/gate.json
{
  "minTotalCoverage": 90,
  "minFileCoverage": 80,
  "exclude": ["**/*.test.ts", "**/__init__.py"]
}
Use exclusions deliberately

Exclude generated, trivial, or intentionally undocumented files. Do not use exclusions to make a thin explanation look complete.
