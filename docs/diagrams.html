Create · Diagrams

Trace the path without pretending it ran.

Fey diagrams are plausible static control paths from a real entry point. Resolved nodes link to source; dynamic or external calls stay visibly unresolved.

The diagram borrows the grammar of a Feynman map: modules become lanes, calls become exchanges, and every accepted node remains attached to the code it represents.

A static map, not a runtime trace

Fey reads the source and follows a likely call path. It does not claim that the path executed, measure timing, or infer dynamic dispatch with certainty. This distinction keeps the diagram useful without overstating what static analysis can prove.

Diagram invariant

A resolved node must carry an accepted source anchor. A genuinely unresolved call carries resolved: false and no anchor.

Begin where control enters

Copilot discovers repository-specific entry points instead of applying one hardcoded list. Common examples include:

  • HTTP routes and request handlers
  • CLI commands and main functions
  • Event, queue, webhook, and scheduled-job handlers
  • Public exported functions that act as a library boundary
  • Tests that best explain an important workflow

Choose the flows that help a maintainer understand the system. A small repository may need every entry point; a large one usually benefits from the most representative paths first.

Diagram grammar

Lane
A module, layer, service, or external boundary that gives calls a stable horizontal position.
Root node
The single entry point where the flow begins.
Child node
A call or meaningful step reached from its parent. Resolved nodes link to code.
Branch
An alternate path such as validation failure, early return, retry, or error handling.
Unresolved node
A dynamic, framework-owned, or external call that static reading cannot safely map to a local span.

Parallel authoring

After indexing, the parent agent identifies entry points and gives each diagram agent the flow, relevant span IDs, and the diagram contract. Each agent writes one scratch file and returns a short receipt.

diagram scratch layout
.fey/create/diagrams/scratch/
├── place-order/
│   └── diagram.json
├── import-catalog/
│   └── diagram.json
└── reconcile-payment/
    └── diagram.json

Disjoint per-flow directories make a failed diagram independently repairable and keep large prose or JSON payloads out of the parent agent’s context.

Deterministic build

validate and assemble diagrams
node .github/skills/fey-create/bin/fey.js diagrams build .

The builder checks the whole scratch set before writing any final diagram:

  • Diagram and node IDs are unique.
  • Exactly one root exists.
  • Parent references form a tree without cycles.
  • Every lane reference exists.
  • Node kinds belong to the contract enum.
  • Every resolved anchor exists in the manifest.
  • The diagram ID matches its scratch directory.

Branches explain meaningful alternatives

Use branch sections for paths a reader needs to understand: rejected input, authorization failure, retries, idempotency exits, or compensating work. Do not turn every conditional into a branch. The diagram is a teaching surface, not a syntax tree.

Interaction in the viewer

The Diagrams tab renders one collapsible card per entry point. Selecting a resolved node opens the source panel at its anchored span. Each flow also exposes Ask, which sends the flow description and source references to a read-only Copilot invocation for a deeper answer.

Ask receives references, not a copied repository

Fey passes paths, symbols, line ranges, and flow context. The local Copilot CLI opens the files it needs under the user’s existing permissions.

Failure behavior

One invalid scratch diagram fails the build and leaves the previous diagram output untouched. Fix only the failing directory and rerun. This atomic behavior prevents a partially refreshed set from looking complete.
