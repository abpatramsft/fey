Fey gives generative work a narrow contract. Copilot decides what to explain; the CLI decides whether the references and artifacts are structurally valid.

The contract

The model writes the explanation. The code checks its footing.

The creative parts stay flexible. The bookkeeping does not. Every stage leaves a plain artifact that can be inspected, rerun, or rejected.

Step 01

Index the source

A repository-specific script emits real files, symbols, and line ranges. Fey validates every span before it becomes citable.

Step 02

Author against the catalog

Copilot writes pages and diagrams using only accepted span IDs. It may choose the explanation, but it cannot invent the destination of a link.

Step 03

Reduce deterministically

Parallel scratch work is assembled only when anchors, IDs, markers, and diagram relationships pass the schema.

Step 04

Keep the evidence visible

The local viewer keeps prose beside source, flows beside nodes, and change rationale beside the diff that motivated it.

One viewer, five ways to understand the same repository. The visual density changes; the vocabulary does not.

The visual grammar comes from Feynman diagrams because the product itself is about making relationships inspectable.

Two verbs

Create understanding. Improve without losing the thread.

Create

A directed line: source becomes an indexed, anchored explanation that a reader can follow back to the code.

  • Repository-specific span indexing
  • Anchored wiki pages and flow diagrams
  • Narrated working-tree drift and local Q&A

Improve

An exchange: propose, change, measure, and keep only the step that clears every hard gate and climbs the rubric.

  • Isolated branch and worktree execution
  • Objective checks plus protected criteria
  • Reversible handoff as uncommitted changes or a merge

Fey does not claim that generated prose is automatically true. It makes the evidence close, the uncertainty visible, and the acceptance rules executable.

Why trust it

Confidence comes from boundaries, not from a more confident model.

Anchor first

No invented destinations

Pages and diagrams can cite only spans produced by a runnable indexer and accepted by the validator.

Reduce in code

Deterministic bookkeeping

Merging, diagram assembly, coverage, scoring, and commit decisions do not ask a model to grade its own structure.

Show drift

Changes keep their intent

Every visible hunk can carry rationale and authorship, so review starts with purpose and can unfold into proof.

Revert exactly

Rejected work stays rejected

The improve loop restores tracked files and removes candidate-created untracked files before another step begins.

Own the files

Plain artifacts, local viewer

The wiki, manifests, diagrams, notes, rubrics, and history remain readable JSON and Markdown inside the repository.

First run

Go from a repository to a viewable explanation.

Fey is currently distributed as repository or personal Copilot skills. Clone it, copy the pieces you want, and ask Copilot to do the rest.

01

Copy the skills

Add fey-create, fey-improve, and optionally the hook bundle to your repository.

02

Ask for the outcome

Say “Use fey to generate an explainable wiki for this repo.” Copilot loads the relevant skill.

03

Open the local viewer
