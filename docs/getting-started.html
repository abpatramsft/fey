Start

Put Fey inside a repository.

Install the skills where Copilot can discover them, ask for an explainable wiki or improvement run, then open the local viewer against the generated .fey/ bundle.

Fey is currently a repository-first skill and hook collection. There is no hosted service and no published plugin yet. The source repository is the distribution artifact.

Requirements

GitHub Copilot CLI
Copilot loads the skill instructions, inspects the target repository, authors the explainability artifacts, and coordinates improvement proposals.
Node.js 18+
The deterministic indexer runner, validators, local viewer, gates, and improve CLI are plain Node.js programs. No install is required; the optional TypeScript compiler API improves JS/TS extraction.
Git
Create can document a non-git folder, but Drift and the complete Improve workflow require a git repository.
PowerShell 7
Required on Windows only when the Copilot hook bundle is enabled. The hook dispatcher itself is cross-platform Node.js.
Current distribution

The planned Copilot plugin and npm package are documented in improvement.md. Until that work lands, installation means copying the skill folders.

Install in a project

Project installation keeps the exact Fey version beside the codebase. It is the clearest option for a team because the skills and gates travel with the repository.

bash · run from the target repository
git clone https://github.com/abpatramsft/fey.git /tmp/fey
mkdir -p .github/skills .github/hooks
cp -R /tmp/fey/.github/skills/fey-create .github/skills/
cp -R /tmp/fey/.github/skills/fey-improve .github/skills/
cp /tmp/fey/.github/hooks/fey-hook.* .github/hooks/
PowerShell · run from the target repository
git clone https://github.com/abpatramsft/fey.git "$env:TEMP\fey"
New-Item -ItemType Directory -Force .github\skills, .github\hooks | Out-Null
Copy-Item -Recurse -Force "$env:TEMP\fey\.github\skills\fey-create" .github\skills\
Copy-Item -Recurse -Force "$env:TEMP\fey\.github\skills\fey-improve" .github\skills\
Copy-Item -Force "$env:TEMP\fey\.github\hooks\fey-hook.*" .github\hooks\

Copy only fey-create if the repository needs documentation but not the hill-climbing workflow. The hook bundle is optional; without it, the commands still work, but Copilot is not automatically held at lifecycle boundaries.

Install the skills once for your user

For personal use across repositories, place each skill directory under ~/.copilot/skills/ or add the source directory through Copilot CLI’s skills management. Repository hooks remain the more predictable choice when a team needs the same gates.

personal skill layout
~/.copilot/skills/
├── fey-create/
│   ├── SKILL.md
│   ├── bin/
│   └── src/
└── fey-improve/
    ├── SKILL.md
    ├── bin/
    └── src/

Generate the first wiki

Open Copilot CLI in the target repository and describe the outcome. Fey is a skill, so the useful entry point is the request—not a long command with product-specific flags.

Copilot prompt
Use fey to generate an explainable wiki for this repository.

Copilot should inspect the repository, write a tailored indexer, validate the span catalog, author anchored pages, attribute any visible working-tree drift, and start the local viewer.

01

Inspect

Find the languages, modules, entry points, and the smallest useful information architecture.

02

Index

Write or select an indexer and emit validated source spans into .fey/create/manifest.json.

03

Author

Write pages and optional flow diagrams using only span IDs accepted by the index.

04

Serve

Open Overview, Wiki, Diagrams, Drift, and Optimize from the repository-local bundle.

Open the viewer later

The generated explanation lives in the target repository. Start the viewer again without rerunning the generative authoring step:

terminal
node .github/skills/fey-create/bin/fey.js serve .

The default address is http://localhost:4177. Add --port N when that port is already in use.

target repository

│   ├── pages/
│   ├── diagrams/
│   ├── drift-notes.json
│   └── gate.json
└── improve/
    ├── run.json
    ├── directions.json
    ├── rubric.json
    ├── gate.json
    ├── history.json
    └── scratch/

These are normal Markdown and JSON files. Commit them when the explanation or improvement record should travel with the code, or ignore them when the repository treats Fey as disposable local analysis.

Common first-run problems

SymptomWhat it meansAction
Skill does not triggerCopilot has not reloaded the copied skill.Restart the CLI or run /skills reload, then inspect it with /skills info fey-create.
Indexer validation failsA generated span points outside an existing file or line range.Fix .fey/create/indexer.mjs and rerun node .github/skills/fey-create/bin/fey.js index . The prior manifest remains untouched.
Stop hook keeps the turn openCoverage, drift attribution, dashboard readiness, or an improve-run invariant still fails.Read the hook’s concrete report and resolve each item instead of disabling the gate.
Dashboard is not reachableThe process stopped or the recorded port is stale.Start node .github/skills/fey-create/bin/fey.js serve . again against the repository or improve worktree.
