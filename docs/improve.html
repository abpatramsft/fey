Improve

Climb one measurable step at a time.

Fey isolates an optimization run, turns intent into a rubric, collects parallel proposals, applies one change, and commits only when hard gates pass and the score clears the configured delta.

The model proposes and evaluates. The CLI owns state, scope, objective commands, score math, protected criteria, fingerprints, revert behavior, and the final handoff boundary.

The loop

ExploreDirections and rubric
AttemptOne coherent change
DecideKeep or exact revert
Acceptance rule

A candidate is kept only when the evaluated working tree is unchanged, objective checks pass, scope and hygiene gates pass, protected criteria do not regress, and the total score improves by at least minDelta.

Initialize an isolated run

start a codebase run
node .github/skills/fey-improve/bin/fey-improve.js init . --target codebase --title "Optimize this repository"

By default, init creates a sibling git worktree on fey-opt-<source-branch>. The original checkout remains usable. The command prints the worktree path; every later improve command and the Fey viewer must target that path.

Dirty source tree

Initialization refuses pending changes by default. Commit or stash them first. Use --checkpoint only when you explicitly want Fey to stage and commit every current tracked and untracked change before creating the worktree.

--target codebase
Evaluate the repository as a whole.
--target diff
Optimize the purpose and quality of a specified set of changes. Pair it with --scope.
--checkpoint
Explicitly stage and commit all pending source-checkout changes before isolation. Never add it automatically.
--no-worktree
Use a separate branch in the current folder. The user’s checkout is temporarily switched.
--no-branch
Run in place without isolation. This is the least safe option.

Name directions, not tasks

Directions are the axes worth improving: hot-path latency, error handling, cohesion, accessibility, test reliability, API clarity, or another repository-specific property. They explain why a candidate matters without prematurely choosing the implementation.

.fey/improve/directions.json
[
  {
    "id": "robustness",
    "title": "Error handling and edge cases",
    "description": "Make failures explicit and recoverable.",
    "rationale": "Several call sites currently lose error context."
  }
]

Turn directions into a small rubric

Use four to eight criteria. Weights express relative importance; each score has its own maximum. Mark properties that must never trade away with "protected": true.

.fey/improve/rubric.json
{
  "scale": "0..10 per criterion",
  "criteria": [
    {
      "id": "correctness",
      "title": "Tests and build pass",
      "weight": 3,
      "max": 10,
      "direction": "robustness",
      "protected": true
    },
    {
      "id": "clarity",
      "title": "Failure paths are explicit",
      "weight": 2,
      "max": 10,
      "direction": "robustness"
    }
  ]
}

record rejects missing, unknown, non-numeric, and out-of-range scores. It no longer treats omission as a convenient way to remove a weak criterion from the denominator.

Configure hard gates

The rubric measures degree. gate.json defines conditions that must simply hold.

.fey/improve/gate.json
{
  "minDelta": 1,
  "protectedCriteria": ["correctness"],
  "requiredChecks": [
    {
      "name": "tests",
      "command": "npm test",
      "timeoutSec": 300
    }
  ],
  "finalChecks": [],
  "allowedPaths": ["src/**", "test/**"],
  "deniedPaths": [".github/workflows/release.yml"],
  "maxFilesChanged": 20,
  "maxLinesChanged": 800,
  "maxIterations": 20,
  "allowDependencyChanges": false,
  "forbidBinaryFiles": true,
  "scanSecrets": true
}
Objective commands

Tests, build, lint, type-check, or repository-specific validation run at baseline and for every candidate.

Hard gate
Scope

Allowed and denied path patterns keep one step inside the intended surface.

Hard gate
Change budget

File, line, and iteration ceilings prevent a “single step” from becoming an unreviewable rewrite.

Hard gate
Hygiene

Dependency changes need opt-in; binary additions and high-confidence secret material are rejected by default.

Hard gate
Score delta

The total must beat the previous best by at least minDelta.

Decision

A check may use one portable command, or separate bash and powershell fields when validation syntax differs by platform.

Record the baseline

Score the untouched worktree and place the score file under .fey/improve/scratch/. Baseline recording requires a code-clean tree and runs all required objective commands.

record iteration 0
node .github/skills/fey-improve/bin/fey-improve.js record <worktree> --scores .fey/improve/scratch/baseline-scores.json --baseline --label "baseline"

The stored evaluation includes the git HEAD, a working-tree fingerprint, gate and rubric hashes, changed-file summary, objective-check results, Node version, and platform. Candidate acceptance later verifies that the evidence still describes the same state.

Collect proposals without editing code

Set the run to proposing, then dispatch task or custom proposal agents—normally one per direction. Each writes one JSON proposal into the next iteration’s scratch directory.

proposal contract
{
  "direction": "robustness",
  "idea": "Preserve the original error as a cause.",
  "detail": "Wrap the adapter error with operation context.",
  "expectedImpact": "Clarity 5 → 8; behavior unchanged.",
  "risk": "low"
}

The transition back to running validates proposal files and refuses to continue if proposal-phase agents changed production code. This check does not rely only on subagent hook delivery.

Apply and evaluate one candidate

Choose one proposal. Apply exactly one coherent change so the score delta can be attributed to a specific move.

inspect the candidate gate
node .github/skills/fey-improve/bin/fey-improve.js candidate-check <worktree>
node .github/skills/fey-improve/bin/fey-improve.js record <worktree> --scores .fey/improve/scratch/iter-1-scores.json --label "preserve adapter error cause"

Recording freezes the score against the current fingerprint. Editing code, the rubric, directions, or gate configuration afterward invalidates acceptance and requires a fresh record.

Commit only through the acceptance gate

accept or reject
node .github/skills/fey-improve/bin/fey-improve.js commit-if-better <worktree>

On success, Fey stages only the evaluated code paths plus .fey/improve/, creates the optimization commit, records its SHA, and leaves a traceable history. Direct git commits are blocked by the optional hook because they bypass the evidence check.

On rejection:

restore the previous kept state
node .github/skills/fey-improve/bin/fey-improve.js revert <worktree>

Revert restores tracked files and removes candidate-created untracked files. The rejected score stays in history so the Optimize view shows the attempted move.

Run statuses

StatusUse
exploringDirections, rubric, and gate configuration are being authored.
proposingSubagents may write proposals under scratch but may not edit production code.
runningA candidate may be applied, evaluated, accepted, or reverted.
pausedThe clean run is intentionally stopping between iterations.
interruptedAn external failure needs recovery before normal progress resumes.
doneFinal checks pass and the run is ready for user-reviewed handoff.

Hand the result back

Marking a run done executes final checks and commits the final run-state update.

finish and inspect
node .github/skills/fey-improve/bin/fey-improve.js status <worktree> --set done
node .github/skills/fey-improve/bin/fey-improve.js handoff-check <worktree>

Handoff is always user-initiated:

finalize
Squash the net run onto the source branch as uncommitted changes. This is the default review path.
merge
Create a no-fast-forward merge that keeps the work branch as one revertible unit.
cleanup
Remove the worktree and optionally its branch after the result is safely reviewed or landed.

Optimize view

Run node .github/skills/fey-create/bin/fey.js serve <worktree>. The Optimize tab reads directions, rubric, proposal scratch, and history to show the best-so-far frontier, accepted and rejected attempts, criterion scores, summaries, and commit SHAs. It works even when the repository has no create bundle.
